## How documentation-only work is blocked, and where suites are skipped

1. **Stop is triggered by the hook event and project CWD, with no diff-based early return for Markdown.** The file at `$cwd/.pandacorp/verify.sh` marks the project. S:26-89 allows recursive Stop, no local verifier and certain fresh Claude build lease/legacy liveness signals. The Codex adapter calls the same executable with runtime metadata, and a live Codex lease does not suppress it. S:103-112 permits a shortcut on a valid existing stamp. An uncommitted doc edit invalidates cleanliness in the stamp helper, and a newly committed doc edit normally changes `HEAD^{tree}`. A documentation session in another CWD without a local verifier skips project verification via path scope.
2. **A pure Markdown change normally runs no Vitest and never Playwright in light mode.** Stop selects code-like extensions from the union of recorded edits and all dirty/untracked paths, picks explicit unit specs or matching siblings, and ignores e2e and overlay paths. With no candidates or over **50** selected tests it invokes static-only light. Other sessions' dirty code can add unit tests to a docs-only session's run. `PANDACORP_STOP_GATE=full` or a legacy verifier lacking light/test flags invokes the full test runners, although all three audited copies support light. S:114-193; V:261-290. No diff can make the enabled cheap stages automatically skip on a docs-only edit.
3. **Red attribution can make an unrelated failure block docs work.** S:251-295 blocks owner-busy exit 75 before attribution. On other reds it allows foreign red only with a nonempty touched record, a readable repo root, external failure/dirty evidence, and neither an intersection with *any* dirty touched file nor with a path in the failing output. Therefore even a dirty owned Markdown edit can make an unrelated TypeScript or unit failure block Stop. A missing touched record also fails closed. After committing, a real foreign failure can be waived when evidenced and no paths intersect. If output has no parseable evidence and checkout is clean, there is no foreign classification. The hook exits 2 on the remaining red; its self-recursion guard can let a subsequent Stop pass. Claude capture and derived drift can independently return 2 even when the project suite is skipped. S:26-28,228-317; `plugin/hooks/hooks.json:52-83`.
4. **Docs contain direct failure predicates.** `doc-lint.sh` checks the whole project. Scaffold (FT) can fail on required PRD/FRD/WO structural keys and README presence/placeholder. Missing provenance (MC/PP) leaves those drift findings advisory. Any project can fail on a `closing` card older than **48 h**, an uncommented `.env.example` entry or an enforced invalid project skill namespace, even before the `docs/` existence check. Legacy skills can receive rollout warnings. Cross-references, UI design oracle, retired lifecycle vocabulary and status schema drift are advisory. Residual ambiguity is independent of doc-lint and can block all three on an ACTIVE document with the marker. These apply in Stop light, G1, G2 or full verification as selected. Sources: projects' `.pandacorp/status.yaml`; MC `.pandacorp/doc-lint.sh:37-180,205-321`; V:1121-1149.
5. **Engine docs units skip tests at G1 only when their report has no changed test surfaces; docs-only FRDs skip G2 and its independent FRD review.** G1 still runs project-wide statics and can reject. `frdsReadyForG2` requires at least one integrated non-docs work unit, so docs alone never schedule G2. A mixed FRD can run G2. Integrated docs are land-ready and still face G3. On the second matching red it hands back as environment/infrastructure and the batch remains unlanded. Doc-attributed red falls through normal repair handling.
