## 2. Survivorship and preventive value

**Verdict — FAILS.** A red count at Stop or landing cannot estimate what would happen if agents lost the earlier test signal. A developer who fixes a failing old test before queueing, or implements a missing case because the acceptance test exists, contributes a green to the final gate. A suite with preventive value would show unchanged pre-existing tests failing on intermediate trees, corresponding fixes in product code, and green final landings. A suite teaching the spec would also show deliberately created reds. Those need separate labels.

The original worker scan found **253 failing outputs** across **276 Codex sessions** and **43 candidate sequences, 32 unique**, with an unedited test failing before non-test source changed (MEASURED screening counts). That sequence alone also captures expected red-first development, incidental source changes and stale tests. The Stop census omitted manual verifies, Codex hook failures and nested Claude subagents. In the earlier queue corpus, “none/unknown” means the scan saw no prior gate. EP046 in that group of partially observed prior evidence had a full green from a subagent **45 s** before enqueueing. A branch using full verify before enqueue could also have changed after that run. Sources: `S/findings/ratio.md:129–131,167–181`, `A/out/episodes-audit.md:10,22–25,59–71`.

There is concrete overlap between reviewers and tests. The Funko ingest reviewer found the continuation bug through a new Postgres probe after **287 files / 1,016 existing Vitest tests had passed** (MEASURED historical report). The export reviewer reproduced a successful retry response with a still-failed persisted job. Removing either the review or its executable regressions affects the same detection chain. Two independent tests and matching source repairs are visible in Git for erasure credentials and timezone-dependent export hydration. Their timestamps and subjects establish that both problems were explicitly exercised. They do not establish what an agent would have done without the checks. Sources: `F/docs/reviews/gate-frd-06-franchise-backfill-codex-2026-10-19.md:7–28`, `F/docs/reviews/gate-frd-05-checklist-export-codex-2026-10-19.md:26–34`, `git -C F show -s --format='%h %ai %s' 0489c73a 665c5f76 b5c6dec0 e7b65f06` → independent erasure test / credential fix and independent reset-date test / timezone fix.

The independent recheck now distinguishes first discovery from enforcement. Of **33** eligible worker failures, **13** drove planned behavior, **10** exposed or reproduced a defect fixed in product code, **9** involved test/fixture/harness corrections and **1** was an unresolved sandbox failure (MEASURED adjudications). **Two** of the ten were consistent with new discoveries. One pre-existing test caught a new request-body bound regression during implementation; the other exposed a stale response overwriting a newer state. Among the two named Stop manifestations, **0–1 new discoveries** are attributable to the hook (ESTIMATED). The older queue had **four** demonstrated bad public/operator outcomes among **26** owned/repair reds plus a blocked unbuildable candidate (MEASURED adjudications). Eight reds on the ledger day had zero demonstrated product fixes. These are different populations. Sources: `S/findings/verify-ratio.md:7–11,110–114,130,148,174–182`.

**Design correction.** Withdraw the pooled Stop-plus-queue percentage as a marginal benefit estimate. Preserve existing tests, make new examples optional when they duplicate an existing oracle, and retain mandatory domain invariants on risky changes. Record first detector, prior test provenance, red tree, actual fix tree and pre-existing vs newly written assertions. Outcome-driven test writing and selective *execution* are separate decisions. The external audit also found no primary source for the reported **1.7%** selection / **18.8% to 4.8%** result (figures are ESTIMATED/unverified here). Remove it as evidence for choosing a suite size. Source: `S/findings/verify-sources.md:17–22`.

**Verdict — FAILS** as the principal release oracle. Independent review remains valuable as a way of discovering missing tests and challenging intent. External primary measurements cut both ways. CR-Bench's best systems detected about **33%** of known defects in its study (MEASURED by authors, repository review with LLM judging). **Design correction.** The protected executable contract judges known invariants. The fresh reviewer examines new failure modes and can reject with reproducible evidence or an inspectable contract violation. Pin the spec-derived oracle before exposing the reviewer to the implementation, or split the read-only spec stage from diff review. Keep cross-family authorship where DR-080 requires it and record the actual pairing and fallback. For a sensitive release, unavailable review parks the change with proof still required. A green rerun or reviewer opinion cannot waive a failing oracle. Measure held-out defect recall, false blocks requiring a fix to the test/spec, elapsed review time, quota waits and owner interruptions. A per-card reviewer on trivial work can cost more than the gate it replaces.

## 6. The two rival recommendations

**Verdict — SURVIVES WITH CHANGE.** Both alternatives deserve a real constituency.

## Decision after the attacks

### A. Corrected recommendation

Change the feedback loop first. Give agents fast affected tests and repair-specific diagnostics. Short-circuit genuinely inert docs G1 and verifier-busy/no-edit Stops. Preserve spec-driven tests that prevent repeat defects. Keep the full rebased proof for launched products and blocking MC browsers under current owner decisions. Add meaningful assertions to production-build smoke using the current build. Pilot selective landing in shadow on lower-risk work. Promote only a bounded class for which the omitted coverage and actual elapsed benefit have been measured. This is Outcome 2 in how work is organized, with Outcome 3 retained at the consequential release boundary pending evidence.

### B. What the original had to change

Drop the pooled catch rate and the savings forecast as decision evidence. Replace the reviewer veto/approval monopoly with protected deterministic invariants plus independently testable review findings. Replace extension-based docs skipping and guessed critical percentages with proved dependencies and project-specific existing tests. Preserve current proof and explicit production order. Classify infrastructure for diagnosis without certifying by retry. Bring nightly receipts and containment forward, before any coverage moves there. Remove broad engine-role redesign, weekly reviewer sweeps and new ledger/owner maintenance as prerequisites for trying the cheapest change.

### C. Residual risks requiring an owner choice

Keeping full pre-release proof leaves real latency and false blocks in the near term. Even a full suite can miss wrong production settings, unmodeled states and scheduling failures. A later narrow lane could permit temporary UI regressions, and a stale nightly could lengthen exposure across more than one release. Any permission to accept that window should name the eligible project and failure classes. Privacy, destructive data operations, processing spend and outage recovery have different consequences. A passed route smoke, a clean test ledger and a successful app rollback each leave some of those consequences untested. Time waiting on an owner, a busy main or a model quota will remain a factor regardless of suite selection.

### D. Cheapest experiment to settle the largest open doubt

**Start without a gate change or a second full run.** Freeze candidate selection rules before examining outcomes. Replay them against the recorded *pre-fix rebased diff* and failing IDs from the old Funko episodes, plus the specific historical catches above. Keep a holdout unseen by the selector author. Count an unknown mapping as unknown, not a hit. On the next ordinary landings, record what the candidate profile would select **before** the existing full run. Join to that same run's per-test outcomes, event times, SHAs and stamp result. Do not run the omitted tests twice. On representative changes where a new smoke or production build split has no timing record, time the candidate separately in an isolated slot and report additional cost. Full-green episodes alone validate neither selector recall nor prevention.

Use a small paired pilot on inert/low-risk work, alternating current and friction-only agent workflow while keeping identical final proof. Record ready-to-enqueue, repair reason, active agent time, owner/busy pause, actual implementation dispatch, gate time, abandonment and first material finding. This distinguishes faster test execution from faster coordination and from moved work. Have a separate reviewer adjudicate disagreements against reproduced behavior, without knowing which lane produced a finding. **Reject** promotion on the first missed material historical or live invariant, a missing nightly receipt or failed containment. Continue with the existing gate if end-to-end gains disappear once new review and setup are charged. A sample of **20** independent changes with zero misses would still allow a **13.9%** one-sided 95% upper bound on per-change missed defects (ESTIMATED binomial illustration, `1 - .05**(1/20)`; correlated changes weaken it). A small pilot can refute the design quickly. It cannot certify rare production risk.
