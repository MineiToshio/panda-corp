**Situation:** a rule intended for multi-figure SETS ("sets get box-only treatment, no loose view") was
applied to every item shown together in a group display photo. One of those items was actually an
INDIVIDUAL figure (a chase variant) that happened to be photographed alongside the set for display
purposes — applying the set-level rule to it incorrectly removed its loose/standalone view, which it
was entitled to as an individual item. The owner caught the mistake and corrected it.

**Lesson:** a batch rule's scope is usually defined along one axis (e.g. "is this a set"), but items get
grouped in a run along a DIFFERENT, incidental axis (e.g. "these were photographed together" or "these
share a display shelf"). Applying the rule to the group as photographed/displayed, rather than to the
group as classified by the rule's own axis, silently catches items the rule was never meant to touch —
and because the mistake looks like "I applied the rule consistently," it's easy to miss without an
explicit per-item check.

**Apply next time:** before applying any batch/group-level rule, re-derive each item's OWN
classification on the rule's specific axis (set vs. individual, in this example) from its canonical data,
not from how it happens to be grouped/displayed in this particular run — a shared photo, a shared shelf,
or a shared source batch is not evidence of shared classification. When a rule's scope and the run's
grouping don't provably match 1:1, verify each item individually rather than applying the rule to the
whole visible group.
