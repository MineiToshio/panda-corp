**Situation:** a portfolio rebuild consistently over-indexed on "codes with AI" across multiple
independent surfaces (hero copy, a metrics strip, a dedicated "how I use AI" section, supporting blurbs),
and separately overcorrected into implying hand-coding as unchanged default practice. Both readings were
wrong in the same underlying way: they picked ONE pole (AI-only or hand-only) as the identity, when the
owner's actual position is a two-part claim — proven capability without AI tooling, and a deliberate,
current choice to orchestrate AI instead.

**Lesson:** for a developer positioning themselves around AI-orchestrated work, "I use AI heavily" and
"I can build without it" are not in tension and both need to stay visible — dropping either one distorts
the positioning. This is a distinct failure mode from getting a single fact wrong: it is copy drifting
toward whichever pole is easiest to write persuasively about (AI orchestration makes for punchier modern
metrics; "I still do it by hand" makes for a reassuring credibility claim), rather than representing the
actual, both-things-are-true stance.

**Apply next time:** when drafting AI-orchestration-forward positioning copy, treat "capability without
AI" and "current AI-orchestrated practice" as two claims that both need explicit, honest coverage across
the surfaces that matter (hero, metrics, methodology) — audit the full set of surfaces together rather than
approving each one in isolation, since the skew is only visible in aggregate. Word the framing as proven
hand capability PLUS a deliberate current choice to direct AI, not one displacing the other.
