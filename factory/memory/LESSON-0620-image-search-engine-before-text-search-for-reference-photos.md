**Situation:** a photo-research step for a physical collectible item tried general text web search first,
hit blocked/paywalled retailer pages, and concluded no official render existed for several named items
(Sasuke 1040, Naruto 1968, Kakashi 1103) — when in fact each item's official 3/4 render was the FIRST
result on an image search engine (Google/Bing/DDG Images) all along. A separate, corroborating incident on
the same project found the same gap for a whole product line (Vinyl SODA): the project's text-search-based
method repeatedly concluded "no aplica" (not applicable) for items that, per the owner's own domain
knowledge, always have a feature (a can) — while a plain image-search query by item name surfaced the
correct asset at the first result every time.

**Lesson:** for sourcing a reference photo of a SPECIFIC named physical product, a general text web
search (crawling article/retailer pages, which are often blocked, paywalled, or simply don't surface the
image directly) is the wrong primary tool — an image search engine indexes and ranks the actual visual
asset directly and surfaces the canonical render/photo as a top hit far more reliably. Treating a failed
text search as evidence "no official asset exists" is a false negative, not a sourcing dead end.

**Apply next time:** for any photo/reference-image research step for a specific named item, query an
IMAGE search engine (Google Images, Bing Images, DuckDuckGo Images) FIRST, by the item's precise name/SKU.
Only fall back to text web search (and only to find a page that HOSTS the asset, not as the primary
discovery method) if the image search genuinely returns nothing usable. Don't conclude an asset "does not
exist" or a classification "does not apply" from a text-search failure alone — a quick image-search check
is cheap and catches both missing-asset false negatives and domain-rule false negatives (e.g. assuming a
product category exception rather than checking the actual item).
