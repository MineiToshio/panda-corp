## Problem
A freshly-created git worktree for a Next.js (App Router) project fails its `tsc`/typecheck gate with
an error about the missing global `PageProps` type (or an equivalent Next-generated route type) until
someone manually runs `pnpm exec next typegen` inside the worktree. Next.js generates these route-aware
global types into a `.next/types/` directory, which — like `node_modules` and other build output — is
never checked out by `git worktree add` and is not currently regenerated by the factory's shared
bootstrap step.

## Root cause
`plugin/templates/shared/.pandacorp/worktree-bootstrap.sh` (and its deployed copy,
`plugin/templates/shared/.pandacorp/worktree-bootstrap.sh` → every project's `.pandacorp/
worktree-bootstrap.sh`) reconstitutes dependencies (step 1: `pnpm install`), `launch.json` (step 2),
`e2e/server-env.json`'s PORT (step 2b), and secrets/data references (step 3), but has no step that runs
`next typegen` (or an equivalent) for a Next.js project, so `.next/types/` is simply absent in a fresh
worktree until the project's own typecheck/dev/build command happens to generate it as a side effect —
which a `tsc`-only gate run does not trigger.

## Fix plan
1. In `worktree-bootstrap.sh`, after step 1 (dependency install) and using the same `$APP_DIR` resolution
   already in place, detect a Next.js project (e.g. `next` present in the resolved `package.json`
   dependencies, or a `next.config.*` file) and run `pnpm exec next typegen` (or the project's own
   equivalent script if one exists) before the bootstrap finishes.
2. Make this step a no-op (not an error) for a non-Next.js project, and tolerant of a `next typegen`
   failure that is itself informative (surface it, don't silently swallow it) rather than blocking the
   whole bootstrap on a typegen hiccup unrelated to this fix's purpose.
3. Bump plugin PATCH + `OVERLAY_VERSION` (shared template changed); regenerate manifests; record in
   `plugin/docs/decision-log.md`.

## Tests (prove the fix — TDD, RED → GREEN)
A fixture-backed test (in the existing worktree-bootstrap test suite, e.g. `plugin/scripts/
test-worktree-bootstrap.sh`) that creates a minimal Next.js-shaped fixture worktree with no `.next/
types/` present, runs the bootstrap script, and asserts `.next/types/` (or the specific generated route
type file) now exists — RED before the fix (bootstrap does nothing for this case), GREEN after.

## Done when
- [ ] `worktree-bootstrap.sh` runs `next typegen` for a detected Next.js project and is a safe no-op for
      a non-Next.js one.
- [ ] The new regression test is green; the existing bootstrap test suite has no regression.
- [ ] Plugin version + `OVERLAY_VERSION` bumped, manifests regenerated, decision-log entry recorded.

## Out of scope
Any framework other than Next.js; this item only closes the specific `PageProps`/route-type gap.
