# Oracle recipes: how the build reproduces each captured state

S2.6 output. The table of states is `oracle-states.json` (one entry per captured state of every UI FRD, copied from `docs/design/freeze/fidelity.config.json` `states`, with the build-side columns added). The machine-readable seed, route rules and doubles are `oracle-recipes.json`; this file is the same content in prose. The prototype side never changes here: the implementer must not edit the prototype, the references, the fixtures or these tables (DR-080).

## 1. Seed: the fixture factory

Every state renders from the privacy-safe fixture factory at `docs/design/prototype/fixtures/` (generated by `scripts/make-fixtures.mjs` from `fixtures/specs/`; the prototype's `data/snapshot.js` and `data/extras.js` are exports of the app's own readers over it). Do not copy it: `reference/fixtures/README.md` points here.

```sh
# paths relative to mission-control/ ; same values as fixtureEnv() in make-fixtures.mjs
PANDACORP_FACTORY_ROOT=docs/design/prototype/fixtures/factory-root
HOME=docs/design/prototype/fixtures/home
PANDACORP_EVENTS_FILE=docs/design/prototype/fixtures/home/.claude/dashboard-events.ndjson
PANDACORP_CODEX_EVENTS_FILE=docs/design/prototype/fixtures/home/.codex/dashboard-events.ndjson
PANDACORP_ACCOUNTS_FILE=docs/design/prototype/fixtures/pandacorp-vault/services/accounts.yaml
GIT_DIR=docs/design/prototype/fixtures/.no-git
GIT_CEILING_DIRECTORIES=docs/design/prototype/fixtures
MC_CLOCK=2026-10-21T00:20:00.000Z
```

- **Frozen clock** `2026-10-21T00:20:00.000Z`: server side by preloading `freezeClock(MC_CLOCK)` from `make-fixtures.mjs` (a `globalThis.Date` override), browser side by Playwright `context.clock` fixed at the same instant. Relative times («hace 25 min») depend on it.
- **Git** is `fixtures/git-state.json` through `fixtureGit(repo)`; real git is blocked by `GIT_DIR`. Five repos: the factory (`/workspace/panda-corp`) and the four projects (`/workspace/<id>`).
- **File times**: every fixture file is stamped clock minus 3 h; an overlay must restore that.
- **Read-only**: the committed fixture is never edited by the build or the gate. A double is an overlay on a temp copy, or a harness-level seam (below).

## 2. Routes: prototype hash to the app's real URLs

The `build.route` column is the canonical path form of `src/lib/navigation/urls.ts` (the legacy query form is parsed too). Query keys that have no codec yet are kept verbatim and architecture fixes their spelling; the oracle only needs the same visible state.

| Prototype | App route |
|---|---|
| `#inicio` | `/` |
| `#tablero` | `/board` |
| `#idea?idea=<id>&tab=<T>` | `/board/<id>[/proposal|spec|architecture|documents|campaign]  (Propuesta, Spec, Arquitectura, Documentos, Campaña)` |
| `#portfolio[?view=lista|cuentas]` | `/portfolio[?view=…]` |
| `#portfolio?project=<p>&tab=<T>` | `/portfolio/<p>[/summary|spec|architecture|changes|observability|documents|commands|accounts]  (Resumen omitted, Spec, Arquitectura, Cambios, Observabilidad, Documentos, Comandos, Cuentas); `Work orders` is the legacy alias that lands on observability` |
| `#logros[?tab=<T>]` | `/achievements[/missions|trophies|statistics|ranks]  (Resumen omitted)` |
| `#propuestas[?tab=<T>]` | `/proposals[/memory|backlog]` |
| `#documentacion?page=<slug>` | `/manual/<group>/<slug>  (group from the Manual snapshot: tutorial, guides, concepts, workflows)` |

- Unknown idea, project, tab or manual page: the route calls `notFound()`, and the oracle's designed not-found state (`idea-not-found`, `portfolio-project-not-found`, `project-tab-not-found`, `docs-page-not-found`) must be what that page draws.
- `observability-legacy-link` (`/portfolio/mission-control/work-orders`) must land on Observabilidad (`redirects_to`).
- `demo=off`, `host=page` and `theme=<t>` are capture params of the prototype. The build applies the theme by its own mechanism.

## 3. Comparison rules per entry

- Default: L1 to L4 of the fidelity target (`fidelity-checklist.md`), every state x width x theme listed in the entry's `prototype.widths` and `themes`.
- **Data-model canvas (owner M1 decision 2, `freeze/m1-decisions.md`)**: `#diagram` is compared by computed styles only (component `ModelDiagram`, states default, entity-selected, zoomed-out) and masked out of the L3 pixel slices. Seven entries carry a `canvas` block, each with the widths at which the canvas exists (verified with Playwright on the prototype: at 375 the default model view is the schema list, so `idea-architecture` and `project-architecture` have the canvas only at 768 and 1280, while the explicit `model=Diagrama` states have it at every width).
- **Manual body (audit blocker 6)**: `docs-page-tutorial` and `docs-page-guide` carry content that REQ-08-013 orders the v2 build to refresh («Portfolio → Party», waves 2/4/8). `.manual-live` is therefore compared by computed styles only (component `ManualBody`, state default) and masked out of the L3 pixel slices at every width; the page chrome around it (heading, breadcrumb, index, neighbour links) is compared as usual. Two entries carry a `content_region` block shaped like the canvas one.
- **Floating panel**: `fragua-token-card` carries `prototype.anchor_offset` (the `FraguaToken` tooltip: panel box minus anchor box, ±1 px, at light-375, light-1280 and dark-1280), copied from `reference/computed-styles.json`. It is the only floating panel in the config.
- `fragua-off` compares `section.fragua` only (see its double). `guild-achievement-notice` carries a fallback mask if the preview affordance is not built.

- **Reached in the prototype by:** applyScenario('snapshot-stale').

The committed git-state.json has no entry for this probe: the double adds it, the committed file is not edited.
- **Must hold:** Both thresholds exceeded => `isSnapshotStale()` true => amber notice «Este commit quedó atrás del build».

## 5. Findings for the lead and the owning FRDs

- **F1 Reader-generated sentences differ from the oracle's Spanish.** Four scenarios (backlog-errors, model-invalid, worktrees-unreadable, stats-stream-error) show a sentence the prototype wrote in Spanish. The installed readers emit English reasons (`malformed YAML frontmatter`, `duplicate id … (already defined in …)`, `git read failed: …`, data-model validator messages). The file or git fault reproduces the STATE; the build must either map the reader's reason to the same Spanish copy or the detail line is masked in L3. Decide in the owning FRD, not in the gate.
- **F2 accounts-source-error cannot be a file fault.** A broken accounts.yaml empties the whole directory in readServicesDirectory() (accounts: []), while the oracle keeps every account and adds two notices. It needs the reader-level injection described in the double. The reader also lacks the `dangling` code and the file-path sources the oracle draws (FRD-26 contract to align).
- **F3 Actions replay verbatim against prototype selectors.** build.actions is `replay-verbatim`: the build gate runs the same click/fill/waitFor/scroll/js actions. The build must expose the same hooks (data-action, data-*, ids, roles) or S2.6 adds a per-state `build.actions` override. The distinct selectors are listed in `action_selectors`.
- **F4 Clock and git seams do not exist in src yet.** Nothing in src reads MC_CLOCK or a git-state double. Server side: preload make-fixtures.mjs freezeClock(MC_CLOCK) (globalThis.Date override) with NODE_OPTIONS=--import. Browser side: Playwright context.clock fixed at the clock. Git: pendingMerge already takes an injectable GitRunner (feed it fixtureGit); achievements/report/scalars.ts shells `git rev-list --count HEAD` directly and falls back to 0 under the dead GIT_DIR, while the oracle shows the git-state.json commit count, so it needs the same seam.
- **F5 Prototype-only URL params are not route state.** demo=off, host=page and theme=<t> are capture params; the build applies the theme by the app's own mechanism. `scene=on|off|sim` is a demo override: on equals the default profile, off is the scene-off double. `achievement=preview` is a review affordance (double achievement-preview).
- **F6 Two states reach UI by script, not by user input.** shell-rail-float sets `#sidebar[data-float=true]` and the a11y/token states call `.focus()` from js. The build keeps the same `data-float` attribute (AppShell, components.md) and runs the same js; no double.
