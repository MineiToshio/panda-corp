# Portable prototype CSS

The approved prototype's main `<style>` block (`docs/design/prototype/index.html`), split into standalone files by component family so the build can lift a component's exact rules without reading the whole prototype. Every rule is verbatim and keeps its `@media` / `@container` wrapper; the one rewrite is relative `url()`s, rebased for this folder. Each file's header lists the prototype lines it came from. Generated by the design-freeze fidelity tools (`split` stage): edit the prototype, not these files.

## Load order

Link the files **in this order**: where two rules of equal specificity touch the same element, the later file wins, exactly as the later line won in the prototype.

## Verification

- **Completeness (mechanical):** the prototype's rules and the concatenation of these files, parsed into normalised `(wrapper chain, selector, declarations)` triples and compared as multisets: **1593 rules in the prototype, 1593 in the files, 0 missing, 0 extra.**
- **Render identity:** the `identity` stage renders a copy of the prototype whose `<style>` is replaced by `<link>`s to these files in this order, and requires every capture to be pixel-identical (`docs/design/freeze/state.json` records the last result).
- Every rule was filed by the configured component map.
