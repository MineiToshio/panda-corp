## Fidelity target

The target is layered, measured and the same for every project; the owner approves it through one sentence: *"a simple vista no se distingue del prototipo, con fuentes y colores exactos"*. Source: `factory/standards/design.md` §5d (DR-129).

| Layer | What | Target |
|---|---|---|
| **L1 Typography and colour** | computed `font-family`, `font-size`, `font-weight`, `line-height`, `letter-spacing`, text and background colours, border colours, shadow, opacity | **100% exact** |
| **L2 Geometry** | box sizes; spacing and radius; anchor offset of every floating panel from its trigger | **sizes exact; spacing and radius ±1 px; anchor offsets ±1 px** |
| **L3 Pixels** | each oracle state against the live prototype, in consecutive viewport-height slices | **per slice ≤ 0.5% of pixels differ** above YIQ threshold **0.1**, anti-aliased pixels ignored |
| **L4 Coverage** | every state the FDD lists | **100% of states × widths (375 touch / 768 / 1280) × themes (light / dark)**; axe **0 serious/critical** |

- **Comparator pinned: pixelmatch 7.x semantics** (`threshold: 0.1`, `includeAA: false`), exact version in the toolkit's lockfile. pixelmatch 8 changed the colour metric, so the numbers are not comparable across the major.
- **"Listed" is the toolkit's scope cap** (`scope.mode: pareto`): every state at 1280 light, layout states at 375 touch, dark for the colour properties, component images at 375 + 1280 light. Wider coverage (768 for every state, dark pixels everywhere) goes to `.pandacorp/comms/visual-punch-list.md` unless an FRD needs it. Pixel states that the FDD names at 768 (the tablet icon rail, the by-FRD dependency map) are listed with that width in the oracle table.
- **Target gate mode: `blocking`** (the factory default, DR-129), pending complete and calibrated project wiring. **Current implementation (2026-10-31): advisory audit only**, see [calibration status](fidelity-calibration-2026-10-31.md). The owner explicitly requires three stable passing runs with complete coverage before enabling a project L1–L4 gate; the uncalibrated 0.5% L3 target must not block integration. Once that prerequisite is met, a measured L1–L4 mismatch blocks the FRD. Judged nits stay advisory per DR-072, and leftovers below the bar go to the punch list for the end-of-build Visual QA. An infrastructure failure (missing prototype, font, image, browser, reference, fixture, lost touch emulation) is always RED.
- **No loosening without a measured flake.** A number above is relaxed only after the same render run twice on an unchanged build produced the difference, with both runs recorded. The implementer never edits the prototype, the references, the fixtures, the oracle table, the tolerances or the gate (DR-080).
- **Product-specific additions (owner decision M1, 2026-10-22):**
  - **Dependency map** (`observability-deps-frd`, `observability-deps-wo`, `observability-deps-focus`, `observability-deps-frd-open`, `observability-deps-list-open`): the build follows the prototype's layouts, "Por FRD" compound boxes and "Por work order" columns by depth. It is pixel-compared (L1 to L4) like any other state.
  - **Data-model canvas** (`model-diagram`, `model-entity-selected`, `model-zoomed-out`; the diagram element is `#diagram`): the build keeps the app's current layout engine (owner-approved 2026-10-16). The canvas is compared by computed styles only (L1 and L2 on the recorded `ModelDiagram` component, entity cards, badges, toolbar), and is **excluded from L3**: the oracle table masks `#diagram` with the build's `[data-oracle-mask="model-canvas"]`. Everything around it (tab bar, search, Diagrama/Esquema control, the teal "Modelo diseñado, no verificado contra una base viva" chip, the page frame) stays pixel-compared. The `Esquema` view (`model-schema`) and `model-none` are fully pixel-compared.
  - **Illustrative pixel noise:** the La Fragua pixel crew idles with a bob animation and the courier walks. Both are paused at `currentTime` 0 before capture (render conditions below); no mask is needed.

## Fonts

Three families, all SIL OFL 1.1, **self-hosted in the build with the same `@font-face` rules as the prototype** (never `next/font` with a renamed family or an added fallback face; if `next/font/local` is used it must emit these exact family names and files). The rules, verbatim from `prototype/base.css`:

```css
@font-face{font-family:'Space Grotesk';font-style:normal;font-weight:300 700;font-display:swap;src:url('…/SpaceGrotesk.ttf') format('truetype')}
@font-face{font-family:'JetBrains Mono';font-style:normal;font-weight:100 800;font-display:swap;src:url('…/JetBrainsMono.ttf') format('truetype')}
@font-face{font-family:'Inter';font-style:normal;font-weight:400|500|600|700|800;font-display:swap;src:url('…/inter-<weight>.ttf') format('truetype')}
```

Exact `font-family` stacks the build must compute (L1, string-exact):

| Role | Token | Computed stack |
|---|---|---|
| Display (h1 750/32px, h2 700, h3 650, card titles) | `--font-display` | `"Space Grotesk", "Inter", system-ui, sans-serif` |
| Body (15px/1.55, `font-feature-settings: "cv11","ss01"`) | `--font-body` | `Inter, system-ui, -apple-system, "Segoe UI", sans-serif` |
| Code, ids, commands, paths | `--font-mono` | `"JetBrains Mono", ui-monospace, Menlo, Consolas, monospace` |

Browsers serialise the computed `Inter` stack without quotes; `computed-styles.json` holds the exact strings. Baselines are blessed only after `document.fonts.ready`. Numbers use `font-variant-numeric: tabular-nums` (`.num`); big display figures use proportional figures. Nothing renders below 12px.

## How to verify (executable gate)

An FRD is not done until every check below passes for **every oracle state of that FRD** in `oracle-states.json` (which covers every route and state its FDD lists), at each listed viewport and theme. The gate renders the live prototype as its reference on every run; it never compares the build with its own earlier screenshots (a self-baseline may exist only as a regression guard after the oracle check passed).

**1. Where it runs, and failing closed.**
- Runs on the local build engine and on the owner's machine, against a checkout that has the whole `docs/design/prototype/` folder (assets, data, fixtures, icons, reference). A worktree gets it through `.pandacorp/worktree-bootstrap.sh`, which must fail when the main checkout lacks it.
- **Fail closed.** A missing or empty asset pack, prototype, font file, reference file, fixture or browser, a prototype image still incomplete after the settle step, or a lost touch emulation makes the gate RED, never skipped and never a pass.

**2. Render conditions.**
- Viewports 375 (touch), 768, 1280; themes light and dark; device scale factor 1; one Chromium build for both sides; base viewport height 900 px. A state's `viewports` list restricts it.
- **Demo chrome off and host auto-detection off:** every prototype URL carries `?demo=off&host=page` (plus `&theme=<theme>`), whichever tool builds it. A capture taken without them is invalid whatever the diff says; the probe `![...document.querySelectorAll('[data-demo-only]')].some((e) => e.getClientRects().length > 0)` must read false on every capture, including the project Resumen where La Fragua's demo block lives.
- **375 is a touch phone:** `isMobile` + `hasTouch`, plus CDP `Emulation.setEmulatedMedia` with `hover: none`, `any-hover: none`, `pointer: coarse`, `any-pointer: coarse`. A `matchMedia` probe taken with every capture must read `(hover: hover)` false and `(pointer: coarse)` true at 375, and the opposite at 768 and 1280; otherwise the capture fails.
- Theme: `prefers-color-scheme` emulated on both sides, and the prototype also pinned with `&theme=`. The build runs in a fresh context with no stored theme choice and no stored sidebar preference (default: open, pinned).

**3. The two sides.**
- **Prototype:** `docs/design/prototype/index.html` opened from the repository (over `file://` with `--allow-file-access-from-files`, or `python3 -m http.server 1988 --bind 127.0.0.1` from `docs/design/prototype/`), then the state's recipe (route hash, fill, click, wait). Fonts and images load from `assets/`; nothing is fetched from the network.
- **Build:** the app is started with the fixture factory as its data (`PANDACORP_FACTORY_ROOT=<repo>/docs/design/prototype/fixtures/factory-root`; `HOME`, `PANDACORP_EVENTS_FILE`, `PANDACORP_CODEX_EVENTS_FILE` and `PANDACORP_ACCOUNTS_FILE` pointed into the same `fixtures/` folder; git answered from `fixtures/git-state.json`; clock frozen at `2026-10-21T00:20:00.000Z`), exactly as `docs/design/prototype/scripts/make-fixtures.mjs` `fixtureEnv()` and `fixtureGit()` do for the exporters, and as `OPEN-MOCKUP.md` documents for `capture-manual.mjs` (`next dev` against the fixture root). The state is reached through its `build` column in `oracle-states.json`: route, profile, seed, test doubles and real actions (§ 8). Fixture images (sprites, ranks, zones, brand) are served as **original bytes, unoptimised**: no `next/image` resizing, re-encoding or format conversion, same intrinsic size.

**4. Capture.**
- **Settle (both sides):** wait for `document.fonts.ready`; scroll through the document in 700 px steps to trigger lazy images, then back to the top; **force every lazy image to load and require every image complete** (8 s cap, then RED if one is still incomplete or broken); then 500 ms.
- **Full-height states: grow the viewport to the document height** (`max(scrollHeight)`, re-measured until stable, capped at 65,000 px) and screenshot the viewport; restore 900 px afterwards. **Never use Playwright `fullPage`**: it drops the touch emulation mid-capture.
- Overlay states (dialogs, sheets, menus, the token tooltip, the rail float, the phone drawer): the 900 px viewport only (`capture: "viewport"`).
- **Pause infinite animations** (the Fragua bob and courier, spinners, pulsing rooms) at `currentTime` 0 before reading styles or shooting; use `animations: 'disabled'` and `caret: 'hide'` on both sides so finite animations are at their end state.

**5. Pixel comparison (L3).**
- The two captures must have the same size; a height difference is a failure (layout drift), except below a masked region declared to differ in height.
- Cut each capture into consecutive **900 px slices** and compare slice by slice with the toolkit comparator: `node /Users/Shared/Proyectos/panda-corp/plugin/skills/design/scripts/fidelity/diff.mjs pixels <reference.png> <candidate.png> --slice 900 --threshold 0.1 --max-ratio 0.005`. Every slice must pass; one failing slice fails the state.
- **Masks** come only from the state's `masks` in `oracle-states.json`: the prototype selector for the mask and the build's `[data-oracle-mask="<kind>"]`. Read every matching box on each side after the settle step, rounded outward to whole pixels; the two sides' boxes must coincide within 1 px on every edge or the state fails as layout drift. **Paint them on the two captured PNGs, never in the page**: every pixel inside the union of the boxes becomes opaque magenta `#FF00FF` in both images, then the images are diffed. Mask kinds for this product: `model-canvas` (`#diagram`, the data-model canvas, M1 decision) and relative-time or timer text that the frozen clock does not fix (none expected with the frozen clock). Any other mask needs an FDD reason and a row in the oracle table.

**6. Computed-style comparison (L1, L2).**
- For every component and state in `computed-styles.json` that belongs to the FRD's routes, at each width and theme, read the build element's computed styles after the state's `read_after_ms` (normal motion settings, infinite animations paused) and compare with the recorded values for the root and every listed child. The automated check is `node /Users/Shared/Proyectos/panda-corp/plugin/skills/design/scripts/fidelity/diff.mjs styles docs/design/prototype/reference/computed-styles.json <build>/computed-styles.json [--component Name]`, fed by a capture of the build with the same `measure` protocol.
- **Selector contract:** the build keeps the prototype's ids, class names and `data-*` / `aria-*` attributes on every recorded element and on the ancestors its selectors pass through (`#sidebar`, `.pagehead`, `.card-head`, `.saga-head`, `.fr-station`, `.token[data-wo]`, `.dag-node`, `.fdag-box`, `.cmd`, `#dlg`, `#diagram`, …), so the recorded selectors resolve unchanged (a utility-class-only build still adds them as semantic hooks). An element that cannot be resolved fails. A root or child recorded as `display: none` passes when the build element is absent or computes `display: none`.
- **Floating panels** (the token tooltip `#tok-tip`, the floated sidebar rail, selects, the phone menu): the panel's raw `position`, offsets and `transform` are **not** compared. Instead, in the open state, the offset of the panel box from its anchor box (dx and dy between the top-left corners of their `getBoundingClientRect()`) must equal the prototype's within **1 px**; the reference values are recorded as `anchor_offset` in `computed-styles.json` and copied onto the recipe by S2.6. Every visual style of the panel and its children is compared as below. Panels render in place, never through a portal or a floating-positioning library.
- **The data-model canvas** (`ModelDiagram`, states `default`, `entity-selected`, `zoomed-out`) is compared here and only here (M1): its recorded entity cards, badges and toolbar must match on L1 and L2; the positions of the entity cards (the layout engine's output) are not compared.
- The compared properties are exactly those recorded in `computed-styles.json`:

| Group | Properties | Rule |
|---|---|---|
| Typography | `font-family`, `font-size`, `font-weight`, `font-style`, `line-height`, `letter-spacing`, `text-transform`, `white-space`, `text-overflow` | exact |
| Colour and paint | `color`, `background-color`, `background-image`, border colours, `box-shadow` and `outline` colour, `opacity`, `filter`, `mix-blend-mode` | exact |
| Sizes | `width`, `height`, `min-height`, the bounding box `W×H`, border and outline widths, `grid-template-columns` tracks | exact |
| Spacing and radius | `padding`, `margin`, `gap`, `top`, `right`, `bottom`, `left`, `outline-offset`, `border-radius`, shadow offsets, blur and spread | within 1 px per length |
| Transforms | `transform`, `translate` | exact |
| Transitions | `transition` | same properties, durations and easing |
| Layout keywords | `display`, `position`, `z-index`, `visibility`, `cursor`, `object-fit`, border style | exact (floating panels: anchor-relative geometry above) |

**7. Accessibility (L4).** A separate run with reduced motion emulated: axe (WCAG 2.2 AA) on every oracle state after it settles, 0 serious or critical; no horizontal overflow at 320, 375, 768 and 1280.

**8. Test doubles for states the product reaches only with external effects.** Mission Control is read-only over the factory and runs no job of its own, so the doubles are data, not services, set per state by the harness in gate and test builds only, absent from production builds:
- **Live build** (`fragua-on`, `fragua-real`, running tokens, «Construyendo ahora»): the fixture's event stream and work-order states; the clock is frozen so «hace N min» texts equal the prototype's.
- **Safety states** (failing work order, build «sin señal», the six read errors, calm Inicio, empty factory, drift badge): seeded by the fixture variant named in the state's `build` column; a read error is produced by pointing a reader at a malformed fixture file, never by mocking the reader.
- **Git facts** (worktrees, «⎇ N pendientes», last green commit, phase history): `fixtures/git-state.json` through an injected git runner; the real repository is never read by a gate state.
- **Plugin version drift** (`plugin-banner`, the sidebar pill): `fixtures/home/.claude` holds the installed version.
- **Clock:** `2026-10-21T00:20:00.000Z` on both sides.

**9. The gate's report** lists, per state and context: the media probe, the host-detection probe, the slice results, the style mismatches (property, expected, actual), the floating-panel offsets (expected, actual) and the mask boxes used.

**Also checked, outside the numbers:** no hardcoded colours (the prototype's own 881 literal px lengths are an acknowledged preflight warning, the build uses the `@theme` tokens); icons come from `docs/design/prototype/icons/*.svg` at the context size and stroke 1.8; strings identical to the prototype plus the confirmed corrections; every state the FDD lists is exercised, including any state specified only in text, built from the frozen components.
